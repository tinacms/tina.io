---
title: 运行本地 GraphQL API
---

_TinaCMS CLI_ 可用于使用 TinaCMS 架构配置设置您的项目，并运行 TinaCMS GraphQL API 的本地版本（使用您的文件系统内容）。要查看实际使用示例，请查看 [TinaCloud Starter](https://github.com/tinacms/tina-cloud-starter)。

## 安装

`@tinacms/cli` 包将作为开发依赖项通过 [tina init](/docs/setup-overview/#manual-setup-on-an-existing-site) 命令安装。

```bash
npx @tinacms/cli init
```

这将在您的站点中设置一个示例 `tina/config.{js,ts}`，并安装任何所需的 TinaCMS 依赖项。

## 运行 GraphQL API

`tinacms dev` 将把架构编译成静态文件，为您生成 TypeScript 类型以在项目中使用，并在 [http://localhost:4001](http://localhost:4001) 启动一个 GraphQL 服务器。

此命令还接受一个参数 (`-c`)，允许您作为子进程运行一个命令。这对于运行开发服务器和构建您的 next.js 应用非常有帮助。您的 package.json 的 scripts 部分应如下所示。

```json
"scripts": {
  "dev": "tinacms dev -c \"next dev\"",
  "build": "tinacms build && next build",
  "start": "tinacms build && next start",
  ...
},
```

我们希望与我们的网站一起运行 GraphQL API 的原因是：

- 当我们的静态页面在 CI 中构建时，它们可以使用 GraphQL API 从本地文件中获取内容。
- 在开发中，我们可以使用本地文件测试 TinaCMS。

现在，如果您运行更新后的 `dev` 脚本：

```bash
npm run dev
```

或

```bash
yarn dev
```

您的实时站点将运行，同时也会运行 GraphQL 内容 API 的本地版本。

您的控制台可能会显示如下内容：

```sh
> yarn dev

Started Filesystem GraphQL server on port: 4001
Visit the playground at http://localhost:3000/admin/index.html#/graphql
Generating TinaCMS config
...
```

一旦 GraphQL 服务器运行，您可以通过 Altair 客户端在 `http://localhost:3000/admin/index.html#/graphql` 开始探索您的 GraphQL 内容。
