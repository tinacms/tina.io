TinaCMS 提供多种管理媒体的选项。

![media-manager-image](/img/media-manager-ui.png)

所有的媒体配置都在 `config.media` 下的 `defineConfig` 函数中完成。

示例：

```ts
export default defineConfig({
  //...
  schema: {
    collections: [
      // 集合数组
    ],
  },
  media: {
    // 媒体配置
    tina: {
      // 基于仓库的媒体配置
    },
    // 加载媒体存储的函数
    loadCustomStore: async () => {},
  },
  //.. 其他配置
})
```

> 注意：只能配置基于仓库的媒体或外部媒体提供商，但**不能同时配置两者**

## 按文件类型过滤

媒体管理器的工具栏有一个类型过滤器，用于将大型库缩小到图像、视频、音频或文档。

从声明了[`accept`](/docs/reference/types/image#restricting-file-types)的图像字段打开管理器时，会用一个锁定的芯片替换该控件，库中只显示字段接受的类型。

仅当媒体存储可以按扩展名过滤时才显示过滤器。基于仓库的媒体、TinaCloud 媒体和本地开发服务器都可以；`staticMedia` 不能，因此该控件在此处隐藏。

## 基于仓库的媒体（默认）

使用内置的基于仓库的媒体选项，媒体存储在网站的仓库中。

基于仓库的媒体将您的资产与内容放在一起，便于跟踪更改和回滚代码和媒体的版本。

这种方法通过消除外部媒体服务器的需求简化了工作流程，因为所有更新都在统一的系统中进行。

[在此处阅读有关基于仓库的媒体的更多信息](/docs/reference/media/repo-based)
