**事件日志**是TinaCloud为您的项目的一个分支所做工作的记录：索引内容、同步媒体以及在此过程中遇到的任何错误。当某些操作失败时，您需要知道原因，这就是您要查看的地方。

## 查找事件日志

日志是按分支而不是按项目保存的，因此您需要从您感兴趣的分支打开它。

1. 在[TinaCloud仪表板](https://app.tina.io)中打开您的项目。
2. 转到**配置**选项卡。TinaCloud知道的每个分支都列出了其当前状态。
3. 打开分支行末尾的菜单，选择**事件日志**。

> 由于日志是按分支保存的，因此在创建新分支时失败的保存事件会记录在该**新**分支上，而不是在`main`上。如果找不到失败原因，请检查错误中提到的分支，而不是您的默认分支。

## 阅读条目

每一行代表一个事件，按时间顺序从新到旧排列。错误用图标标记，以便您在繁忙的日志中挑选出来。

错误行有两个部分。第一部分是TinaCloud正在做的事情，例如，索引一个分支。第二部分是根本原因，通常是出错的具体内容，并且通常会提到负责的文件：

```
无法播种内容/posts/my-post.mdx
原因：val.replace不是一个函数
```

某些事件没有记录原因，在这种情况下，行中会说明这一点，而不是留空。

使用底部的**加载更多事件**可以进一步回溯历史记录。

## 常见原因

大多数索引错误来自与您的模式不匹配的内容。以下是一些常见的情况：

- **字段类型错误。** 定义为`type: 'string'`且`list: true`的字段必须包含纯字符串。列表中的对象或未加引号的数字将导致索引失败，原因通常提到`replace is not a function`。
- **未定义的块模板。** 如果MDX块的`_template`不存在于集合的`templates`列表中，则无法索引。
- **缺少媒体目录。** 如果`mediaRoot`指向的文件夹不在存储库中，即使内容索引成功，媒体同步也会失败。

索引在遇到第一个无法读取的文件时停止，因此修复原因中提到的文件并重新索引通常会揭示下一个问题（如果有多个问题）。

## 修复内容后

提交已更正的文件，然后从打开日志的同一分支菜单中选择**重新索引**。日志将显示一个新的索引事件，成功运行意味着编辑者可以再次保存。

如果原因不明确，或者重新索引后同样的错误再次出现，请将消息和分支名称发送至[support@tina.io](mailto:support@tina.io)。
