随着这一年的结束，我和团队花了一些时间回顾 TinaCMS 从年初到现在的进展。2021 年初，TinaCMS 是一个新兴的开源项目，Forestry 团队对其充满了建设的热情。这个项目在很多方面与今天你所了解的 TinaCMS 大相径庭。今年的旅程涉及到对开源项目的一些重大改变，但我们的使命始终如一：提供一个开源的 CMS，为全球最优秀的网页开发者和内容编辑者提供 10 倍的体验。

今年早些时候，我们收到了许多使用 TinaCMS 的大小公司的反馈。我们了解到 TinaCMS 太过开放，试图做得太多。我们决定设置一些限制，以缩小 TinaCMS 的关注点，但为更多用户提供更好的整体体验。我们选择 Next.js 作为 TinaCMS 当前的首选框架（而不是 Gatsby 等），专注于存储在 Git 中的内容，而不是支持任何数据存储，并将页面内编辑体验替换为你现在看到的并排编辑体验，以改善整体开发者体验。此外，我们为 TinaCMS 添加了一个 [GraphQL API](/docs/graphql/overview/)，它不仅提供了 Git 支持的内容的所有好处（版本控制、内容所有权、分支等），还增加了一个可以轻松查询的结构化 API。

现在，到了十二月，TinaCMS 已经有了显著的发展。我们对 2021 年取得的成就感到非常自豪。我们缩小了 TinaCMS 的关注点，并为未来基于 Git 的内容编辑奠定了坚实的基础。

在新的一年里，我们期待分享我们对 2022 年的愿景，并讨论我们为 TinaCMS 计划的所有令人兴奋的功能。

## 一月至三月

在 2021 年的前几个月，我们仍在作为一个产品寻找自己的定位，我们的愿景是无论用户选择了什么 CMS，都能轻松编辑内容。我们投入了大量工作来改善我们现有的功能体验，并添加了一些我们认为对社区重要的新功能。我们还增加了 3 名团队成员，以推动开发者和用户体验。

## 2021 年四月

四月是云产品的发布。Scott Gallant（CEO）于 2021 年 4 月 21 日宣布推出 TinaCloud，强调了由可视化编辑驱动的 Git 支持内容的重要性。我们希望提供一种使用 Git 的一流体验，并允许没有 GitHub 的用户编辑内容。如果你有兴趣再次阅读原始公告，这里是[链接](/blog/tina-cloud-a-headless-cms-backed-by-git/)。在回顾时，我们对仅仅 8 个月后的现状感到非常兴奋。

## 2021 年五月

### 全力投入 Next.JS

五月是我们全力投入使用 Next.js 的时候，吸引我们的是：

* 动态导入
* 灵活的数据获取
* Next.js 正在成为 Jamstack 的领导者，并拥有一个很棒的社区。

使用单一框架帮助我们快速迭代，专注于正确的问题，而不是担心我们支持的每个框架的边缘情况和细微差别。

## 我被聘为开发者倡导者

我们觉得我们走在正轨上，需要更多的开发者使用 TinaCMS，以便我们能够保持创新的势头。五月底，我们聘请了一位开发者倡导者（嘿，就是我！）来与我们的受众（嘿，就是你！）联系，我们觉得准备好开始建立我们的社区。在被聘用之前，我对 TinaCMS 的概念和 TinaCMS 在研究视频后所做的事情很感兴趣。我永远不会忘记我在那个视频中说的话，

"TinaCMS 非常强大，我将只展示它能做的表面。"

在与团队讨论 TinaCMS 的愿景后，我全心投入，我不想做其他事情或去其他地方。感觉就像昨天，但现在已经七个月过去了，我仍然有同样的感觉！

## 2021 年七月

我们收到的最常见和最有影响力的反馈之一是关于媒体管理的。你们想知道为什么不能使用 TinaCMS + Cloud 管理媒体。我们知道这是用户面临的一大障碍，所以我们立即开始研究解决方案，并引入了与 Cloudinary 的集成。我们选择 Cloudinary 是因为：

1. 支持所有图像类型
2. 优化的图像
3. Next Image 喜欢 Cloudinary

我们希望尽可能简单地为你的网站添加 Cloudinary 支持。因此，我们创建了 `next-tinacms-cloudinary`，它负责繁重的工作，通过最小的集成，你的网站就准备好了！

## 2021 年十月

### MDX 支持

到目前为止，我们一直专注于开发者，但我们也希望确保我们为内容编辑者构建。我们为 TinaCMS 引入了 MDX 支持，以便开发者可以创建团队所需的所有可重用组件，并允许你的内容团队通过单击一个按钮来重用这些组件。这个功能真正体现了 TinaCMS 的核心，为开发者和内容编辑者提供无缝体验。

### 文档入门

我们还引入了一个 TinaCMS 文档入门，允许文档团队快速入门，使他们能够通过单击一个按钮创建新页面和编辑页面。这个入门也由 MDX 驱动，因此不仅可以通过单击一个按钮开始，你还可以添加团队可能需要的所有可重用组件，以创建出色的文档。

## 2021 年十一月

### 文档改进

在十一月，我们着手从各个方面审视我们的文档，以确保无论你想如何使用 TinaCMS，都能获得所需的信息。我们召集了团队，每个人都带来了不同的视角，这些视角来自他们的经验、用户研究和你的反馈。这个练习带来了巨大的改进和精致的文档，以便你获得所需的一切。

### 仪表板入门改进

我们还添加了使用 GitHub 帐户登录的功能，使一切更容易整合在一起。通过一个简单的快速入门流程，你可以登录，选择我们的一个入门，并让我们为你部署。基本上，这意味着你可以在几分钟内测试和使用 TinaCMS。

## 2021 年十二月

十二月通常是一年中较慢的时间，但 TinaCMS 不是这样。我们仍然有一些实验性功能和一种新的 TinaCMS 入门方式，希望在年底前提供给你。

### 简约入门

我们引入了一个名为 "简约" 的新入门，它为你提供了一个带有 TinaCMS 的最小 Next.js 项目。这使你可以通过最小的 TinaCMS 集成在一步中启动一个新的 TinaCMS 项目。我们在简约入门之前的入门包含了许多用于特定任务的额外代码，例如我们的文档入门。我们希望为你提供一个良好的基础，而不需要任何额外的代码或依赖项。

### `create-tina-app`

我们还引入了 `npx create-tina-app`，它允许你使用你选择的入门来设置一个 TinaCMS 应用程序。作为开发者，我们理解本地工作的重要性，它允许你调查幕后发生的事情。通过一个命令，你可以在本地调查 TinaCMS，进行更改，然后再部署。

**自动生成的 GraphQL 客户端（实验性）**

虽然我们喜欢 graphQL，但我们理解对于那些不太熟悉它的人来说，编写 graphQL 可能是令人生畏的。为了解决这个问题，我们引入了一个实验性功能，允许你使用一个客户端。这使得熟悉 javascript 的开发者可以使用点表示法来获取他们需要的数据。例如：

```javascript
const tinaProps = await client.getPostsDocument({relativePath:"helloWorld.md";});
```

你可以在我们的 [GitHub](https://github.com/tinacms/tinacms/blob/main/packages/%40tinacms/cli/GeneratedClientDocs.md) 上查看如何使用这个实验性功能。

### 分支支持（实验性）

允许 TinaCMS 驱动的网站切换到任何分支是我们一直在努力的事情。分支对开发者和内容团队来说非常重要，因为如果他们想推出新功能或帖子，他们当然不希望它立即上线。我们希望确保我们做对了，通过使用户体验易于导航，我们刚刚将其作为实验性功能发布。你可以在 [我们的文档](https://tina.io/docs/tinacloud/branching/) 中找到如何实现这一点。

## 下一阶段

年初，TinaCMS 是一个实验性的开源项目，过于开放，难以维护所有的活动部件。我们支持数十个不同的包，从收到的反馈来看，这不是最佳方法。在对如何改进我们的方法做出艰难决定后，我们现在有了一个坚实的产品，正在生产网站中看到越来越多的使用。

在我们的下一篇文章中，我们将描述这一切的发展方向以及我们对 2022 年 TinaCMS 的计划。整个团队对进入项目的下一个阶段感到非常兴奋，并希望你能查看并给我们诚实的反馈。我们想听听你使用 TinaCMS 的项目以及我们可以做些什么来使其更简单、更快或更好。
