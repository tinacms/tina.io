In May we told you [what we're planning for TinaCMS v4](/blog/tinacms-v4-is-coming). We promised five things: plugins, better forms, better fields, Git workflows inside the editor, and a fresh editor UI.

Six months and a lot of pull requests later, v4 is starting to feel real. Here's a look at where the herd has got to 🦙.

**TL;DR:** v4 isn't released yet, and v3 is still fully supported. This post is a preview of what's coming.

## 🏠 A brand new home

When you open the v4 admin, you land on **Home**. It's a dashboard of panels that shows your collections, your recent documents and the branch you're on ([#8009](https://github.com/tinacms/tinacms/pull/8009), [#8050](https://github.com/tinacms/tinacms/pull/8050)).

A rail runs down the left side, and collections open right beside it. The Top bar holds a Branch switcher, so you always know which branch you're editing. A Status bar along the bottom tells you what TinaCMS is doing.

Every button, field and tooltip now comes from one design system, so the whole editor feels like it belongs together ([#7990](https://github.com/tinacms/tinacms/pull/7990)).

## 💾 Saving you can trust

Losing work is the worst. v4 keeps your unsaved edits as drafts, so a reload or a closed tab doesn't wipe them out ([#7627](https://github.com/tinacms/tinacms/pull/7627)).

When a field has a problem, the Save button changes to **Resolve 1 error**. Click it to see an error summary that takes you to each field that needs a fix ([#8031](https://github.com/tinacms/tinacms/pull/8031)).

Edited five documents? Use **Save all** in the Top bar to save them in one go ([#8061](https://github.com/tinacms/tinacms/pull/8061)).

The fields got a rebuild too. Each field shows its errors under it once you leave the field or try to save, and the Image field shows your picture as a tile, a cover or a gallery ([#7945](https://github.com/tinacms/tinacms/pull/7945), [#7988](https://github.com/tinacms/tinacms/pull/7988)).

## 🔌 Plugins all the way down

This is the big change under the hood. In v4, media, search, login and even whole screens are plugins. A plugin can have a client side, for the screens and controls editors use, and a server side, for operations, secrets and file access. You can add plugins, swap them out or replace them, and you don't need to fork TinaCMS to do it ([#7706](https://github.com/tinacms/tinacms/pull/7706)).

Your config lists the plugins you use, including your own, like a custom rating field:

```ts
import { defineConfig, mediaManagerPlugin, tinaCloud } from '@tinacms/tinacms';

export default defineConfig({
  plugins: [
    tinaCloud({ clientId: process.env.TINA_PUBLIC_CLIENT_ID }),
    mediaManagerPlugin(),
    ratingFieldPlugin,
  ],
  schema: { collections: [postCollection] },
});
```

One `tinaCloud()` line gives you content, login and media. Add a `search` option and it gives you search too ([#8057](https://github.com/tinacms/tinacms/pull/8057)). Want your own media provider instead? Write a plugin for it.

## 🧭 Make the admin your own

The sidebar and the admin panel aren't fixed anymore. Any plugin can add its own entry to the sidebar, with a label and an icon. An entry can open a screen inside TinaCMS, open a link in a new tab, or run an action ([#7686](https://github.com/tinacms/tinacms/pull/7686)).

Home is a screen too. If your team wants its own dashboard, like publishing stats or a content calendar, swap out Home for your own screen ([#8050](https://github.com/tinacms/tinacms/pull/8050), [#7706](https://github.com/tinacms/tinacms/pull/7706)).

```tsx
export const dashboardPlugin = definePlugin({
  name: 'northwind:dashboard',
  provides: ['screen'],
  overrides: [{ capability: 'screen', key: 'home' }],
  client: async () => ({
    default: defineClientPlugin({
      screens: [{ name: 'home', label: 'Home', component: NorthwindDashboard }],
      slots: {
        globalNav: [
          {
            label: 'Style guide',
            icon: BookIcon,
            target: { kind: 'url', href: 'https://northwind.com/style' },
          },
        ],
      },
    }),
  }),
});
```
