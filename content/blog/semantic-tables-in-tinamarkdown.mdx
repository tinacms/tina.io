We're continually blown away by the great developer community that help us improve TinaCMS. We get some great pull requests and we recently merged a PR that was worth a shout-out.

A big thanks to [@lastenvoy30](https://github.com/lastenvoy30) for your PR that helped improve the way that our HTML tables are rendered, and ultimately improved a11y.

`TinaMarkdown` used to render every row of a markdown table as `<tbody><td>`, header row included. There was no `<thead>` and no `<th>` anywhere in the output.

The first row of a markdown table now renders as `<thead><th>`, matching standard GFM output and the behaviour TinaCMS already had for tables authored in the editor.

This change was pushed with the aim to improve a11y, since screen readers rely on `<th>` to associate a header with the cells beneath it.

**TL;DR:** Your markdown tables will render different HTML after this release, and they will probably look different too. Nothing in the API changed, so this ships as a minor. Load a page with a table on it before you deploy.

## Why this is a minor and not a major

Nothing in the public API moved. `TinaMarkdown`, its props, and every component override behave exactly as before.

## What you need to change

**If you pass a `td` component override**, add a `th` alongside it. The header row no longer goes through `td`, so without this it renders unstyled.

```jsx
<TinaMarkdown
  content={page.body}
  components={{
    th: (props) => <th className="px-3 pb-2 font-semibold text-left" {...props} />,
    td: (props) => <td className="px-3 py-2" {...props} />,
  }}
/>
```

Expect a visual change: tables will look different after you upgrade, even if you do nothing.

If something feels off, tell us. Open an issue, or drop into [Discord](https://discord.com/invite/zumN63Ybpf) with what you found.
